## Правила заведения

- Проект **mg**; в заголовке маркер **«(из регулярной проверки Bitrix)»** — по нему же ищутся прошлые тикеты (отдельного тега нет).
- Связь **«связана с»** на текущий bxkor-тикет проверки; смежные тикеты — той же связью.
- Поле **«Сервис»** обязательно и по смыслу: по нему воркфлоу ставит тег команды (деск-сервисы → «Команда ОМ №1», публичка → «№2»).
  Встречались: Корзина, Заказ товаров, Заказы (Сотрудникам ОКТ), Коммерческие предложения, Веб-аналитика, Каталог по брендам,
  Баннерная реклама, Карточка товара, Главная страница, Поиск товаров, Установка договоров… в публичной части сайта.
- Та же тема, что у открытого тикета, — комментарий в него, не дубль.
- Описание — Markdown; в YouTrack вставляется как есть (таблицы, код, списки).

## Подготовка вкладки и токен

1. `browser_tabs` → `list`; работать в своей вкладке YouTrack. После `browser_navigate` ждать ~6 с (`browser_wait_for` time 6) —
   иначе снапшот пустой. Редирект на `hub.example.com/hub/auth/login` — попросить пользователя войти самому.
2. `browser_run_code_unsafe` с `filename=.claude/skills/perf-check/scripts/yt/auth.js` — перехватывает Bearer (REST с cookie даёт 401)
   и вешает `window.__yt(path, init)`, `window.__ytSearch(queries, top)`, `window.__ytIssues(ids)`. Токен живёт ~30 мин: на ошибке
   `-> 401` запустить `auth.js` снова.
3. Большие ответы — через `browser_evaluate` с параметром `filename` (путь от корня репо): JSON уходит в файл, а не в контекст.

## Поиск похожих тикетов

```js
() => window.__ytSearch([
  'project: mg "из регулярной проверки Bitrix"',   // все тикеты проверок
  'project: mg hl_apiship_terminal',               // по таблице
  'project: mg /personal/cart/',                   // по странице
  'project: mg kor:offers',                        // по компоненту
  'project: bxkor Выполнить регулярную проверку Битрикс sort by: created desc',  // текущий тикет проверки, если номер не назван
], 50)
```

Ответ: `{запрос: [[id, состояние, сервис, заголовок], …]}`. Запросы с `or`, скобками или `*` в кавычках дают 400 — по одному ключу
на запрос. Затем `() => window.__ytIssues(['mg-180096', …])` — состояние, сервис, связи и теги известных тикетов (реестр —
`references/perfmon.md`). Второй источник дублей — панель «Похожие задачи и статьи» в форме черновика (её читает `fill_NN.js` и `verify.js`).

## Черновик тикета

1. `php .claude/skills/perf-check/scripts/yt/drafts.php <срез>/tickets/tickets.json` — проверка и `fill_NN.js`, `create_all.js`.
2. На каждый тикет: `browser_tabs` → `new` с url `https://youtrack.example.com/newIssue?project=mg` → `browser_wait_for` time 6 →
   `browser_run_code_unsafe` с `filename=<срез>/tickets/fill_NN.js`. Скрипт заполняет заголовок, сервис, описание (Markdown через
   синтетический paste) и связи, возвращает `summaryOk`, `service`, длину описания против ожидаемой, `linked`, `links`, `similar`.
3. Если `linked` для какой-то связи не «отправлено» или её нет в `links` — связать вручную: кнопка «Связать задачи» на панели формы →
   «связана с» → набрать id → Enter → Escape (`browser_snapshot` → `browser_click`/`browser_type`).
4. `browser_run_code_unsafe` с `filename=.claude/skills/perf-check/scripts/yt/verify.js` — сверка всех вкладок с `draftId`.
5. Повторное заполнение того же черновика безопасно: описание перед вставкой очищается.

Черновик виден только автору и сохраняется сам; кнопку «Создать» не нажимать.

## Создание и комментарии (только по команде)

- `browser_run_code_unsafe` с `filename=<срез>/tickets/create_all.js`: создаёт задачи из всех вкладок с `draftId`, где есть маркер,
  сервис, описание длиннее 1 000 символов и связь с bxkor; остальные пропускает и возвращает причину.
- Комментарий: `php .claude/skills/perf-check/scripts/yt/comment.php <id> <текст.md> <out.js>` →
  `browser_run_code_unsafe` с `filename=<out.js>` во вкладке YouTrack. Возвращает `posted`, `already` (такой комментарий уже есть)
  или `status`. Итог в bxkor отправлять после создания тикетов, чтобы в нём были их номера.

## Ловушки

- Случайный ввод с клавиатуры без фокуса открывает диалог команд (`[data-test=yt-command-dialog]`, «Неизвестная команда»), он
  перекрывает кнопки — скрипты закрывают его Escape; при ручных действиях проверять.
- После вставки длинного описания страница прокручивается, клики по координатам промахиваются — `window.scrollTo(0, 0)` или
  выбирать поля до вставки.
- Синтетический paste дописывает к имеющемуся тексту — перед вставкой `Meta+A` + `Backspace` (`execCommand('selectAll')` не срабатывает).
- Инструмент блокирует вывод JS с URL с query string (`location.href` с `draftId=`) — возвращать `location.pathname`.
- В `browser_run_code_unsafe` нет `require` и `fs` — данные вшиваются в JS (так делают генераторы).
